# Эксперименты с редакторским конвейером

Эти возможности находятся в ветке PR #92 и ещё не выпущены как 0.4.0. Пакет сохраняет
версию 0.3.0. Обычные кампании для Telegram, X, DEV и GitHub продолжают работать;
новый конвейер связывает статью, медиа, DEV-черновик и три X-анонса в одной папке.

## Подготовка

Для генерации нужны работающий Ollama и установленная модель. Проверенная ранее
конфигурация — `gemma4:12b` с таймаутом 600 секунд; качество другой модели нужно
оценивать отдельно. Для Quillgrain установи доверенный engine по [инструкции](quillgrain-voice.md).
Открытие, ручная правка статьи и локальное превью не вызывают модель.

Из корня проекта в PowerShell:

```powershell
$env:PATCHPITCH_MODEL = "gemma4:12b"
$env:PATCHPITCH_TIMEOUT = "600"
.venv/Scripts/python.exe -m patchpitch editorial init --config examples/editorial/article.toml --out artifacts/experiment-voice --json
.venv/Scripts/python.exe -m patchpitch editorial init --config examples/editorial/article-preset.toml --out artifacts/experiment-clear --json
.venv/Scripts/python.exe -m uvicorn patchpitch.app:app --host 127.0.0.1 --port 8000
```

Открой `http://127.0.0.1:8000/editorial` и укажи абсолютный путь к выбранной папке.
Каждый новый опыт начинай в отдельной пустой папке; существующие папки не перезаписываются.
Для локальных опытов DEV API key не нужен. Примеры используют проверенные исторические
факты 0.3.0 и публичный демонстрационный профиль, а не обученную копию личного голоса.

## 1. Quillgrain против Clear на одинаковых фактах

В двух подготовленных папках одинаковы факты, язык, авторский ракурс и углы анонсов;
различается настройка стиля. Проверь факты, предложи и отредактируй план, прими его,
затем напиши разделы. Для более строгого сравнения используй одинаковый принятый план
в обоих документах и одинаковые настройки модели.

Сравни конкретность вступления, первое лицо, повторения, неподтверждённые утверждения
и число ручных правок. Засекай своё активное время до приемлемого текста отдельно
от ожидания модели. Успешная сборка Quillgrain доказывает совместимость профиля;
насколько текст похож на тебя, решаешь ты.

## 2. Переписать один раздел и сохранить остальную статью

Сохрани ручную правку во вступлении, закрепи другой раздел, а для третьего попроси
более конкретный пример или более короткое объяснение. Посмотри diff и полную карту
источников, затем прими или отклони предложение.

Проверь, что соседние разделы и их медиа не изменились, а точный код остался исходным.
Попробуй изменить инструкции закреплённого раздела: приложение должно сначала
потребовать разблокировку. Изменение статьи снимает её прежнее подтверждение
и делает зависимые X-варианты устаревшими.

## 3. Закрыть редактор с несохранёнными правками

Измени текст одного раздела и порядок разделов плана, затем перезагрузи страницу
и открой ту же папку. Убедись, что браузерный буфер восстановил слова и порядок.
Сохрани только один раздел: несохранённая правка другого должна остаться на месте.

Буфер браузера ещё не является принятой ревизией. Для переноса на другую машину
используй приватную резервную копию всей рабочей папки. Полный backup содержит
исходники, голоса и ответы модели; публикационный экспорт их не содержит.

## 4. Статья с настоящими медиа

Импортируй свой PNG/JPEG/WebP, GIF и MP4 со звуком. Добавь alt, подписи, обложку,
poster и WebVTT; расставь блоки в нужных разделах. Построй полное превью и проверь
настольную/мобильную ширину, play/pause, перемотку, звук и субтитры.

Это проверка реальных файлов, а не текстовых обещаний сделать скриншот. PatchPitch
импортирует и размещает медиа; запись экрана, монтаж и создание хостинга остаются
внешними шагами. Для DEV нужны уже размещённые публичные HTTPS URL. Видео в DEV
пока экспортируется как poster/CTA к внешнему плееру; локальные controls не означают
встроенный проигрыватель в самой статье DEV.

## 5. Три угла X из одной принятой статьи

Подготовь варианты «польза», «решение/эксперимент» и «пример». Если опыта в фактах нет,
задай другой угол в job вместо выдуманной истории. Проверь шесть тегов, обязательный
`#DEVCommunity`, текст и основания выбора. Измени только второй вариант и сравни два
остальных. Повторная генерация после принятия создаёт новый набор кандидатов.

Пока нет финальной ссылки, вариант доступен для редактирования, но не для копирования
как готовый пост. В управляемом слоте ссылка резервирует 23 символа. После ручной
публикации своей статьи можно проверить и привязать её финальный DEV URL без новых
запросов модели. Если в папке уже есть DEV receipt, ID статьи должен совпасть с ним.
Старую чужую статью нельзя подставить вместо нового черновика.

Отдельно попробуй копию каталога с просроченными наблюдениями: X должен показать
blocker, а локальная статья и её превью продолжить открываться. Шесть тегов означают
проверенную тематическую релевантность, а не обещанный охват. Отправки в X в этом
workflow нет.

## 6. Конфликт с ручной правкой DEV — только в тестовом черновике

Этот опыт требует DEV API key и явного сохранения удалённого черновика. Вначале
посмотри детали доставки: title, ревизию, payload hash и известный article ID.
Дай всем используемым медиа публичные URL, прими статью и сохрани draft.

Измени его описание вручную в DEV, затем попробуй обновить из PatchPitch. Ожидается
конфликт, а не перезапись. Посмотри remote/local diff, выбери нужный текст и только
после проверки используй показанный remote hash. Повтор должен обновлять тот же ID.
Проверь также замену и удаление обложки. Ничего публиковать для этого не требуется.

## Что измерять

Для каждого опыта запиши модель/профиль, число запросов, активное время правок,
количество неподтверждённых утверждений, необходимость внешнего переписывания
и ручных переносов. История и raw responses остаются в рабочей папке, поэтому можно
сравнивать исходный ответ, принятую правку и итог. Ошибку модели полезно сохранить;
валидный JSON сам по себе не означает хорошую статью.

Все операции доступны также через [CLI](editorial.md). Проверки и границы реальных
прогонов описаны в [отчёте реализации](editorial-0.4.0-verification.md); результаты
дополнительного ревью — в [отчёте PR #92](editorial-0.4.0-review.md).
