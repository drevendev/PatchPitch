## Findings before release

1. **DEV reconciliation contract (P2):** `patchpitch/publishers/dev.py:91` substitutes `fully_autonomous` when the owned-article response omits AI disclosure. The real owned-article response observed during delivery omitted that field. A lost write with `some_ai` or `no_ai` therefore cannot match its saved payload hash through `--existing-id`, even if the server saved the exact article. Current fake API tests preserve the field and miss this. Fix the comparison using a trustworthy response contract or explicitly handle unverifiable disclosure; add a regression with the field omitted. Do not simply remove the unrelated-article ownership/content checks.
2. **Remote-main integration before commit:** local main remains at `44ca597`, while remote main includes the media deployment, merged first-run README improvements and publication closeout (`79670c1`). The local README would remove the newer offline-first onboarding if treated as a whole-file replacement. Integrate the development diff on top of current main, preserving both onboarding and new CLI instructions. Backlog/closeout files shown as untracked locally already exist remotely; do not duplicate them.
3. **Quillgrain CI coverage gap:** the workflow installs no Quillgrain engine; integration modules use `pytest.importorskip`. A green ordinary CI run can therefore omit a central 0.3.0 feature. Keep the dependency optional for users, but add an explicit integration job with a trusted pinned engine and fail if the intended integration checks are skipped.
4. **Historical status cleanup:** implementation/live-run documents retain older claims that the DEV article is unpublished and the draft round-trip is pending. They now have follow-up notes, but the release checklist should state the current status directly and separate historical evidence from outstanding work.
