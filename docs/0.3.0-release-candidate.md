## Changes for developers

- Run reviewed-fact or selected-Git campaigns from JSON/TOML jobs with the CLI and closed stdin. No PatchPitch web server or browser is needed. Planning, explicit resume, OS locks, stable run identity and separate original/current outputs support unattended work.
- Prepare Telegram, X, DEV articles and GitHub notes from the same selected facts, edit publication files and restore the campaign in the studio.
- Plan X posts and reserve space for exactly six catalog-backed tags plus the CTA. Stale/insufficient evidence, changed tags and overflowing edits are rejected. Matching is lexical; tag reach is not measured.
- Compile a chosen local Quillgrain pack or verify its bundle with language/register/channel checks and immutable voice context. The optional engine is installed separately; verified revision is `8af17f979c0ad20163bec5fd247279a7a6f5addf` (`0.1.0rc3`).
- Create/update owned DEV drafts explicitly with receipts and `published=false`. Unknown-response recovery identifies the saved outgoing payload without assuming an omitted AI disclosure value, then PUTs the desired content to the same draft. Existing published articles remain protected.
- Retain existing session/profile and legacy X workflows. Installing `.[ui]` adds the studio; the default package has no browser/web-server dependency.

## Installation and supported runtime evidence

Python 3.11+ is required. Install the candidate wheel into a fresh environment; add `.[ui]` from the source checkout if the studio is needed. Start local Ollama and install the chosen model explicitly. Neither the package nor an ordinary CLI run installs/downloads a model.

The verified Linux configuration is Ubuntu 24.04, Python 3.12.15, Ollama 0.40.10, `gemma4:12b` digest `6114515d63c17436a7c0417d82820ac65ad643e2806c5a3c89cb62846436ed0b`, with **PATCHPITCH_TIMEOUT=600**. A CPU DEV request took 497.921 seconds, exceeding the normal 420-second default. Do not assume equal quality/performance from another model: Gemma 3 4B failed this six-fact campaign. See the [full Linux record](linux-live-2026-10-24.md).

Changing runtime version changes run identity by design. Keep the original environment for resuming incomplete older runs; current edited files can be validated/exported separately. Do not rewrite an old snapshot just to bypass the runtime check.
