# Сессии и DevLog из Git

Реализация от 21 октября 2026 года проверена локально; публичный выпуск не выполнялся.

## Что изменилось

Все пять форматов сохраняют исходные source references и identity fact pack. Изменение продукта, аудитории, release label, voice или CTA снимает подтверждение; результат отдельно хранит исходный pack и список изменённых полей контекста. Варианты разных релизов различимы, media brief очищается при загрузке нового входа, а X source map и список пропусков обновляются после rewrite. Предыдущие warnings помечаются историческими.

Devlog с одними обязательными примечаниями больше не требует лишнего highlight. Пустой outline проверяется локально, включая запрет лишнего retained prose.

Download session / Open session сохраняют форму, Include/Exclude, варианты всех форматов, точный текущий Markdown, X порядок и media notes, исходные ответы и ошибки. Сохраняется и незавершённый Git-review: выбранные файлы, diff, кандидаты фактов, их правки и выбор. Восстановление не обращается к Git или модели автоматически. Новый model request требует подтверждения; некорректный файл не заменяет текущую работу.

Product profile содержит только повторяемый контекст продукта и CTA. Заметки конкретного выпуска в профиль не входят. Файлы сохраняются явно; autosave и облачного хранения нет.

При ревью исправлены три пограничных сценария: запись отклонённого входа (HTTP 422) больше не блокирует Save/Open; незавершённый Git-review учитывается при закрытии вкладки и замене сессии; полный допустимый provenance помещается в ограниченный запрос генерации. Предупреждение браузера остаётся best effort и само работу не сохраняет.

## Как подготовить следующий DevLog

1. Запусти приложение через `scripts/start_local.ps1`. После обновления кода перезапусти старый сервер. Открой `http://127.0.0.1:8000`.
2. Раскрой **DevLog from Git**, укажи локальный корень репозитория и выбери Recent commits либо Explicit base and head. Для воспроизводимого примера PatchPitch: base `f5baf58`, head `6f84004`.
3. Нажми **Inspect Git range**. Проверь полные SHA, commit subjects и пропущенные файлы. Subjects служат контекстом; факты извлекаются из net diff. Рабочие незакоммиченные изменения исключены.
4. Выбери файлы. В примере подходят `patchpitch/generator.py`, `patchpitch/static/generation-records.js` и `patchpitch/static/social-editor.js`.
5. Нажми **Review selected diffs**, прочитай изменения и подтверди допустимость их использования. До этого момента inference не выполняется.
6. Проверь все части diff и число запросов, затем нажми **Suggest facts with local Gemma**. Большие diff автоматически разбиваются на части и обрабатываются последовательно. Проверь каждый кандидат по его Dxx, файлу, номеру части и диапазону байтов. Убери повторы, исправь формулировки и явно отметь до 15 фактов для DevLog.
7. **Stop after current request** останавливает обработку после текущего запроса. При ошибке автоматического повтора нет: завершённые части, оригинальные ответы и правки сохраняются. Скачай сессию, открой её позже, подтверди просмотр diff и нажми **Continue remaining batches**. Готовые части не запрашиваются повторно. Применить факты можно после обработки всех частей. Повторный просмотр того же diff сохраняет правки; новая генерация кандидатов требует подтверждения замены.
8. Нажми **Use selected facts for DevLog**, проверь продукт и аудиторию, затем подтверди выбранные notes и нажми **Write the announcement**. Git автоматически использует Development progress: committed не означает released или deployed.
9. Отредактируй результат, проверь Source notes, скачай session и Markdown. Вставь Markdown в редактор площадки, выполни preview и опубликуй вручную.
10. Только после настоящей публикации можно записать её URL через **Record a manual publication**. Скачай сессию: следующий импорт сможет использовать **Since recorded manual publication**. Генерация, export и ошибки сами baseline не сдвигают.

Иллюстративный или записанный URL в тесте не является настоящей публикацией. Приложение не проверяет публикацию во внешней соцсети и не выполняет её.

## Ограничения первого Git importer

Поддерживаются локальные SHA-1 репозитории и ancestor range до 50 коммитов и 200 изменённых путей. Recent mode выбирает baseline по first-parent; сам диапазон включает merged commits. Выбор ограничен 12 текстовыми файлами, 128 KB diff на файл и 192 KB суммарно. Части содержат до 6 KB исходного diff, один запрос — до 12 KB сериализованных свидетельств. Предел одного review — 64 части и 24 последовательных запроса. Байты UTF-8 сохраняются без усечения; длинные строки и hunks могут продолжаться в следующей части, что явно отмечено. Root baseline поддерживается. Reverts учитываются через итоговый net diff.

В редактор попадают только явно отмеченные 1–15 фактов общей длиной до 6000 символов. Остальные кандидаты и оригинальные ответы остаются в Git-review. Сессия сохраняет промежуточный прогресс и допускает продолжение после остановки или ошибки. Прежние сессии открываются без потери исходных правок; для новой обработки старого diff сначала нажми Review selected diffs, чтобы получить план запросов.

Binary/generated/dependency/sensitive filenames показываются как пропущенные. Symlinks, submodules и non-UTF-8 текст не поддерживаются. Превышение бюджета останавливает запрос до модели. Частичная выборка явно отмечается; нельзя считать её полным обзором диапазона. Проверка имён файлов и похожих credentials не заменяет просмотр исходников человеком.

Git не меняет checkout, не запускает hooks, external diff, textconv, сборки, fetch, clone или push. Промпт содержит только выбранные проверенные diff. Source IDs и метки implemented/fix/refactor/uncertain остаются средствами проверки, а не доказательством истинности текста или прохождения тестов.

Session JSON может содержать приватные notes, исходники, model responses и выбранный локальный путь репозитория. Храни его локально. Лимиты файла: 32 MB, 100 текущих вариантов и 200 generation records.

## Проверка обработки больших diff

Полный suite изолированной ветки PR: **277 passed, 15 dependency warnings, 195.81 секунды**. Параллельные изменения проверялись отдельно и не включены в эту ветку. Новые проверки покрывают сохранность каждого байта UTF-8, длинные строки, точный JSON-бюджет запроса, продолжение hunks, полный root baseline, credentials в конце больших файлов, ссылки только на текущую порцию, повреждённые checkpoint-записи, остановку и Save/Open после ошибки. Отдельно проверены сохранение ручных правок при продолжении и выбор факта из пула больше 15 кандидатов. Тестовый сервер использует свободный порт, чтобы параллельные запуски не подключались к чужому процессу. Inference в автоматических тестах — MOCK.

Для воспроизведения большого кейса выбери Explicit base and head: base `6f840045db76fb759bf7c3ab09f20cb0ff449356`, head `c30d213bf9fa2c889d00f1feabf637a689e5b9fd`. Отметь `patchpitch/git_import.py`, `patchpitch/sessions.py`, `patchpitch/static/sessions.js` целиком. Review selected diffs показывает **44 399 байт, 9 частей и 6 последовательных запросов**; каждый из этих файлов превышал прежние 6000 байт. Просмотри части, подтверди их и запусти Suggest facts. После Stop after current request скачай session JSON, открой его через Open session JSON, снова подтверди diff и нажми Continue remaining batches. Ранее завершённые запросы повторно не выполняются.

Этот сценарий выполнен через настоящий интерфейс с локальной `gemma4:12b`, без подмены inference. Шесть запросов заняли суммарно 163.975 секунды и дали 47 кандидатов. После первой порции выполнены Stop, ручная правка и выбор факта, Download/Open в новой вкладке и явное Continue. Первый оригинальный ответ и ручная правка совпадают с промежуточным сохранением, а последовательность принятых порций равна 0–5 без повторов. Конкатенация каждой группы частей побайтно совпала с `git diff` для соответствующего файла; все запросы уложились в JSON-бюджет, ответы завершены без token overflow.

Из 47 кандидатов вручную проверены и выбраны четыре. Например, кандидат с перепутанными байтами и символами исключён; события на кнопках не приняты за доказательство добавления самих кнопок. Исторические лимиты из рассматриваемого коммита не попали в текст о текущем состоянии. Исходные ответы, checkpoint-сессии, проверка фактов и отчёт сохранены локально в ignored `artifacts/git-chunks-2026-10-21/`. Публикация остаётся ручной; issue #63 не менялся.

Выбранные факты прошли через обычный Devlog-редактор: отдельная генерация заняла 49.022 секунды, warnings приложения отсутствуют. Широкие рекламные формулировки исходного английского ответа убраны при явной русской редактуре. `devlog-checked-ru.md` побайтно соответствует текущему Markdown в `session-ready.json`; исходный model response остался неизменным. Четыре источника сохранили stable IDs G001/G013/G015/G041, точный диапазон коммитов, D-ID, файл, номер части и байтовый диапазон.

### Исправления по результатам ревью

Повторный Inspect больше не разрывает связь между выполненными порциями и отредактированными кандидатами. При сбросе preview правки и выбор сохраняются с исходной записью review. Они восстанавливаются только при совпадении точного hash репозитория, диапазона, всех частей и плана запросов. Оригинальные тексты, IDs и порядок порций проверяются; изменённый исходный кандидат не принимается за ручную правку. Save/Open поддерживается и в промежуточном состоянии без preview.

Лимит session JSON поднят до 32 MB для больших журналов checkpoint-ответов. Перед сохранением проверяется размер именно форматированного UTF-8 файла с переводом строки, а не компактного HTTP-запроса. Если файл не поместится, загрузка не начинается и текущая работа остаётся в редакторе. Регрессионные проверки покрывают Save/Open журнала больше 4 MB и отказ при компактном JSON меньше 32 MB, который при форматировании превышает лимит.

## Предыдущая проверка сессий и Git DevLog

Полный suite после ревью: **246 passed, 15 dependency warnings, 107.07 секунды**. Тесты используют MOCK inference. Проверены источники всех форматов, текущий X source map после rewrite, точные Unicode/newlines, несколько форматов и исходные failed attempts после Save/Open (включая отклонённый вход), повреждённые файлы, защита незавершённого Git-review, подменённый diff, root/recent/explicit ranges, merge/revert, ограничения, полный provenance в API и исключение credentials.

Реальный локальный кейс использовал `gemma4:12b`, диапазон `f5baf58..6f84004` и три выбранных файла. Extraction занял 115.003 секунды и предложил девять кандидатов. После просмотра исходного diff оператор отредактировал и выбрал четыре факта. Сохранённый Git-review был открыт через продукт; отдельный запрос дал Devlog за 28.105 секунды без warnings приложения.

После явной ручной редакции проверены Copy, точный Markdown export, Save/Open после refresh и неизменность исходных generation records. Desktop 1440 и mobile 390 не имеют горизонтального скролла, browser errors отсутствуют. Исходные ответы, отдельная редактура и JSON записи сохранены локально в ignored `artifacts/sessions-git-devlog/`. Это операторская проверка; owner acceptance и публикация не выполнялись. Последующие проверки Save/Open выполнялись без новых inference calls.

15 предупреждений зависимостей относятся к уже заведённому issue #69. Они не скрывают ошибок тестов. EN/RU, semantic review и публикационные интеграции остаются отдельными этапами.
