# Сессии и DevLog из Git

Реализация от 21 октября 2026 года подготовлена для PR; публичный выпуск не выполнялся.

## Что изменилось

Все пять форматов сохраняют исходные source references и identity fact pack. Изменение продукта, аудитории, release label, voice или CTA снимает подтверждение; результат отдельно хранит исходный pack и список изменённых полей контекста. Варианты разных релизов различимы, media brief очищается при загрузке нового входа, а X source map и список пропусков обновляются после rewrite. Предыдущие warnings помечаются историческими.

Devlog с одними обязательными примечаниями больше не требует лишнего highlight. Пустой outline проверяется локально, включая запрет лишнего retained prose.

Download session / Open session сохраняют форму, Include/Exclude, варианты всех форматов, точный текущий Markdown, X порядок и media notes, исходные ответы и ошибки. Сохраняется и незавершённый Git-review: выбранные файлы, diff, кандидаты фактов, их правки и выбор. Восстановление не обращается к Git или модели автоматически. Новый model request требует подтверждения; некорректный файл не заменяет текущую работу.

Product profile содержит только повторяемый контекст продукта и CTA. Заметки конкретного выпуска в профиль не входят. Файлы сохраняются явно; autosave и облачного хранения нет.

При ревью исправлены три пограничных сценария: запись отклонённого входа (HTTP 422) больше не блокирует Save/Open; незавершённый Git-review учитывается при закрытии вкладки и замене сессии; полный допустимый provenance помещается в ограниченный запрос генерации. Предупреждение браузера остаётся best effort и само работу не сохраняет.

## Как подготовить следующий DevLog

1. Запусти приложение через `scripts/start_local.ps1`. После обновления кода перезапусти старый сервер. Открой `http://127.0.0.1:8000`.
2. Раскрой **DevLog from Git**, укажи локальный корень репозитория и выбери Recent commits либо Explicit base and head. Для воспроизводимого примера PatchPitch: base `f5baf58`, head `6f84004`.
3. Нажми **Inspect Git range**. Проверь полные SHA, commit subjects и пропущенные файлы. Subjects служат контекстом; факты извлекаются из net diff. Рабочие незакоммиченные изменения исключены.
4. Выбери файлы. В примере подходят `patchpitch/generator.py`, `patchpitch/static/generation-records.js` и `patchpitch/static/social-editor.js`.
5. Нажми **Review selected diffs**, прочитай изменения и подтверди допустимость их использования. До этого момента inference не выполняется.
6. Нажми **Suggest facts with local Gemma**. Проверь каждый кандидат по его Dxx/file, исправь формулировки и явно отметь нужные факты. Это отдельный запрос модели, а не готовый DevLog.
7. При необходимости скачай сессию прямо здесь и продолжи после её открытия. Повторный просмотр того же diff сохраняет правки; новая генерация кандидатов требует подтверждения замены.
8. Нажми **Use selected facts for DevLog**, проверь продукт и аудиторию, затем подтверди выбранные notes и нажми **Write the announcement**. Git автоматически использует Development progress: committed не означает released или deployed.
9. Отредактируй результат, проверь Source notes, скачай session и Markdown. Вставь Markdown в редактор площадки, выполни preview и опубликуй вручную.
10. Только после настоящей публикации можно записать её URL через **Record a manual publication**. Скачай сессию: следующий импорт сможет использовать **Since recorded manual publication**. Генерация, export и ошибки сами baseline не сдвигают.

Иллюстративный или записанный URL в тесте не является настоящей публикацией. Приложение не проверяет публикацию во внешней соцсети и не выполняет её.

## Ограничения первого Git importer

Поддерживаются локальные SHA-1 репозитории и ancestor range до 50 коммитов и 200 изменённых путей. Recent mode выбирает baseline по first-parent; сам диапазон включает merged commits. Выбор ограничен 12 текстовыми файлами, 6 KB diff на файл и 24 KB суммарно. Root baseline поддерживается. Reverts учитываются через итоговый net diff.

Binary/generated/dependency/sensitive filenames показываются как пропущенные. Symlinks, submodules и non-UTF-8 текст не поддерживаются. Превышение бюджета останавливает запрос до модели. Частичная выборка явно отмечается; нельзя считать её полным обзором диапазона. Проверка имён файлов и похожих credentials не заменяет просмотр исходников человеком.

Git не меняет checkout, не запускает hooks, external diff, textconv, сборки, fetch, clone или push. Промпт содержит только выбранные проверенные diff. Source IDs и метки implemented/fix/refactor/uncertain остаются средствами проверки, а не доказательством истинности текста или прохождения тестов.

Session JSON может содержать приватные notes, исходники, model responses и выбранный локальный путь репозитория. Храни его локально. Лимиты файла: 4 MB, 100 текущих вариантов и 200 generation records.

## Проверка реализации

Полный suite после ревью: **246 passed, 15 dependency warnings, 107.07 секунды**. Тесты используют MOCK inference. Проверены источники всех форматов, текущий X source map после rewrite, точные Unicode/newlines, несколько форматов и исходные failed attempts после Save/Open (включая отклонённый вход), повреждённые файлы, защита незавершённого Git-review, подменённый diff, root/recent/explicit ranges, merge/revert, ограничения, полный provenance в API и исключение credentials.

Реальный локальный кейс использовал `gemma4:12b`, диапазон `f5baf58..6f84004` и три выбранных файла. Extraction занял 115.003 секунды и предложил девять кандидатов. После просмотра исходного diff оператор отредактировал и выбрал четыре факта. Сохранённый Git-review был открыт через продукт; отдельный запрос дал Devlog за 28.105 секунды без warnings приложения.

После явной ручной редакции проверены Copy, точный Markdown export, Save/Open после refresh и неизменность исходных generation records. Desktop 1440 и mobile 390 не имеют горизонтального скролла, browser errors отсутствуют. Исходные ответы, отдельная редактура и JSON записи сохранены локально в ignored `artifacts/sessions-git-devlog/`. Это операторская проверка; owner acceptance и публикация не выполнялись. Последующие проверки Save/Open выполнялись без новых inference calls.

15 предупреждений зависимостей относятся к уже заведённому issue #69. Они не скрывают ошибок тестов. EN/RU, semantic review и публикационные интеграции остаются отдельными этапами.
